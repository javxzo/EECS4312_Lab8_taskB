**Cancellation**
- FR5: The system must allow a registered user to cancel, removing them from the registered list.
- FR6: The system must allow a waitlisted user to cancel, removing them from the waitlist and updating all remaining positions.
- FR7: When a registered user cancels and the waitlist is non-empty, the earliest waitlisted user must be promoted to registered.
- FR8: When a registered user cancels and the waitlist is empty, the registered list simply decreases by one with no further action.
- FR9: Canceling a user that does not exist in the system must raise a NotFound exception.
- FR10: Canceling a user that has already canceled must raise a NotFound exception.

- FR11: The system must allow any user to query their status, returning "registered", "waitlisted" with a 1-based position, or "none" as a UserStatus object.

- FR13: A user who has previously canceled may re-register and must be treated as a brand new registrant, joining the back of the waitlist if capacity is full.

**User Identity**
- FR14: User identifiers must be non-empty, case-sensitive strings. "Alice" and "alice" are treated as different users.
